## 1. 프로젝트 개요
### 1.1 개발 목적
실제 레이싱 휠의 Force Feedback(FFB)을 활용하여 운전자와 첨단 운전자 보조 시스템(ADAS)이 물리적으로 상호작용하는 독립형 3D 운전 시뮬레이터를 개발한다.
기존의 단순한 자율주행 게임처럼 AI가 차량 조향값을 직접 변경하는 것이 아니라, ADAS가 실제 G29 휠에 조향 보조력을 전달하고, 운전자가 그 힘을 느끼면서 직접 개입할 수 있는 시스템을 구현한다.
장기적으로 다른 개발자들이 자신만의 ADAS 알고리즘, 차량 물리 모델, 레이싱 휠 드라이버 등을 추가할 수 있는 오픈소스 플랫폼으로 확장한다.
### 1.2 핵심 목표
Logitech G29 입력 및 FFB 제어
독립형 3D 운전 시뮬레이터
차량 물리 및 조향 시스템
차선 유지 보조(LKA)
차로 중앙 유지 보조(LFA)
스마트 크루즈 컨트롤(ACC)
제한된 환경의 자율주행
운전자 조향 개입 및 제어권 전환
실시간 ADAS 시각화
외부 개발자를 위한 확장 API 및 SDK
외부 게임 연동은 후순위 개발 항목이다.
초기 버전은 BeamNG.drive 등과 연결하지 않고 독립적으로 실행할 수 있어야 한다.
### 1.3 프로젝트 차별점
실제 레이싱 휠을 통해 ADAS 조향 개입을 물리적으로 체험
운전자 입력과 ADAS 제어를 하나의 공동 조향 시스템으로 통합
운전자 개입 시 보조력과 제어권이 자연스럽게 전환
조향각, 목표 경로, 차선 오차, FFB 출력을 실시간 분석
다양한 ADAS 알고리즘을 교체하고 비교할 수 있는 실험 환경
향후 다른 레이싱 휠 및 외부 시뮬레이터 지원

## 2. 개발 환경 및 제약 조건
### 2.1 개발자 역량
현재 개발자는 Python의 기본적인 코드 흐름을 이해하고, 오류 발생 위치와 원인을 어느 정도 분석할 수 있다.
직접 작성할 수 있는 코드는 대략 20줄 내외의 소규모 로직 수준이며, 대규모 게임 엔진 개발 및 제어공학 경험은 제한적이다.
따라서 다음 원칙을 적용한다.
대규모 코드 작성은 AI 에이전트가 담당
개발자는 기능 요구사항, 설계 방향, 실제 테스트, 결과 검증 담당
주요 알고리즘의 동작 원리는 개발자가 이해할 수 있도록 설명
핵심 기능마다 간단한 학습 자료와 테스트 예제 제공
한 번에 지나치게 많은 기능을 구현하지 않음
### 2.2 시간 및 AI 사용량 제약
ChatGPT Plus 사용
AI 에이전트 사용량 제한 고려
장시간 연속 개발이 어려운 신체적 제약 고려
짧은 개발 세션에서도 작업을 이어갈 수 있어야 함
모든 개발 단계에서 진행 상황과 남은 작업을 문서화
권장 개발 방식:
하나의 작은 기능 선정
AI에게 구현 요청
코드 및 실행 결과 확인
실제 하드웨어 테스트
문제점 수정
Git 커밋
다음 작업을 위한 인수인계 문서 갱신
AI 사용량이 소진되더라도 다음 세션에서 작업을 이어갈 수 있도록 한다.
### 2.3 저장 공간
초기 단계에서는 대규모 3D 에셋을 사용하지 않는다.
예상 저장 공간:
G29 테스트 프로그램: 약 1~5GB
기본 3D 시뮬레이터: 약 5~20GB
중규모 시뮬레이터: 약 20~60GB
대규모 에셋 및 빌드 보관: 그 이상 가능
위 수치는 개발 계획용 추정치이며 엔진, 에셋, 캐시, 빌드 설정에 따라 달라진다.
개발 초기에는 저장 공간 20~30GB 정도를 확보하는 것을 우선 목표로 한다.

8. AI 에이전트 개발 규칙
프로젝트 진행 시 AI에게 다음 규칙을 적용한다.
한 번에 하나의 개발 단계만 진행한다.
기존 기능을 임의로 삭제하거나 재작성하지 않는다.
주요 구조 변경 전 이유와 영향을 설명한다.
하드웨어 관련 코드는 안전 제한을 우선 구현한다.
실제 테스트를 통과하지 않은 기능은 완료로 표시하지 않는다.
각 기능에 테스트 코드 또는 검증 절차를 제공한다.
사용자가 이해하기 어려운 핵심 코드는 동작 원리를 설명한다.
외부 라이브러리의 역할과 설치 방법을 기록한다.
작업 종료 시 Git 커밋 및 진행 상황 문서를 갱신한다.
AI 사용량이 부족해도 다음 세션에서 이어갈 수 있도록 작업을 작은 단위로 나눈다.
프로젝트에 불필요한 기술이나 라이브러리를 추가하지 않는다.
외부에서 받은 에셋과 SDK의 라이선스를 확인한다.

12. 프로젝트의 최종 성공 기준
프로젝트의 성공은 단순히 차량이 자율주행하는 것으로 판단하지 않는다.
다음 조건을 충족하는 것을 목표로 한다.
실제 Logitech G29를 사용해 독립형 시뮬레이터를 운전할 수 있다.
LKA/LFA가 작동하면 실제 휠에서 조향 보조력이 느껴진다.
운전자가 직접 조향하면 시스템이 이를 반영한다.
운전자 개입 시 보조력이 갑작스럽게 반전되거나 위험하게 증가하지 않는다.
차량 물리와 휠 피드백이 일관되게 작동한다.
ADAS 동작과 실패 원인을 데이터로 확인할 수 있다.
다른 개발자가 알고리즘을 교체하거나 추가할 수 있다.
실제 도로 주행용이 아닌 시뮬레이션 및 연구용 플랫폼으로 안전하게 배포할 수 있다.

13. 향후 개발 재개 시 첫 번째 작업
Phase 0과 Phase 1부터 시작한다.
첫 작업은 다음과 같다.
Windows 11 환경에서 Logitech G29의 조향각과 페달 입력을 읽고 실시간으로 표시하는 최소 프로그램을 구현한다. 이후 안전한 FFB 출력 테스트 기능을 추가한다. 모든 구현은 향후 Godot 기반 3D 시뮬레이터와 연결할 수 있도록 모듈화한다.
초기에는 3D 게임, 자율주행 AI, 복잡한 차량 물리를 구현하지 않는다.
하드웨어 연동과 공동 조향 제어를 먼저 검증한다.
프로젝트 핵심 원칙: 게임의 규모보다 실제 운전자와 ADAS의 물리적 상호작용을 우선한다.
